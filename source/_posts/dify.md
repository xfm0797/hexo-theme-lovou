# Dify

> 可视化编排工作流、内置 RAG 与 Agent、可观测可发布，LLM 应用从原型到生产的中间层

---

> **项目速览**
>

> | --- | --- |
> | 仓库 | [langgenius/dify](https://github.com/langgenius/dify) |

> | 形态 | Web 平台 + API |

## 它想解决什么问题

写一个 LLM 原型只要几十行代码；把它变成可交付的产品却要补一整套周边：提示词管理、知识库、变量、错误处理、日志、权限、接口发布。

Dify 把这套周边标准化：**用可视化工作流表达业务逻辑**，模型、知识库、工具、分支都在画布上，跑通即发布为 API。

## 核心机制拆解

**1. 工作流编排。** 节点化画布支持条件分支、循环、代码节点、HTTP 调用，把"多步 Agent"从代码搬进可视结构，改逻辑不用改代码。

**2. 内置 RAG。** 文档上传、分段、向量化、召回、重排全链路内置，知识库可被多个应用共享。

**3. Agent 与工具。** 支持工具调用与 MCP，内置常用插件市场，也能自己写工具接内部系统。

**4. 运营与观测。** 日志、标注、用量统计、A/B 版本、提示词调试都在平台里，发布后能持续迭代。

## 安装与上手

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker && cp .env.example .env
docker compose up -d
```

打开 `http://localhost/` 建管理员账号，先做一条"文档问答"模板跑通，再改成自己的业务。

## 点评

**亮点**是把"工程化"补齐了：多数 LLM 框架给你代码能力，Dify 给你的是交付能力——权限、日志、发布、版本，这些才是上生产时真正耗时的部分。可视化也让非算法岗能参与。

**局限**：可视化有天花板，复杂状态机与非标准交互最终仍要写代码；平台自己就是一套不小的服务，自托管要维护数据库、向量库、队列与模型网关；高级定制受节点能力约束，深度改造不如自己写框架灵活；社区版与企业版功能有差异，选型前要看清边界。

**适合人群**：要快速把 LLM 应用交付给业务方的团队；缺少专职 AI 工程岗的中小公司；以及想先用低代码验证、再逐步下沉到代码的团队。
