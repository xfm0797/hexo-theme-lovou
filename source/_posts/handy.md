# Handy

> Tauri v2 构建的跨平台听写工具：识别全在本地跑，可换模型、可加热词，隐私零妥协

## 它想解决什么问题

语音转文字本身不难，难的是"不想把音频传出去"。会议记录、医生问诊、律师口述、内部复盘——这些场景里的音频一旦离开本机，合规上就说不清了。

Handy 的选择很彻底：**识别完全在本地完成**，不联网、不上传。同时它没有把"离线"当成功能缩水的借口，模型可换、热词可加，日常听写够用。

## 核心机制拆解

**1. 本地推理。** 音频在设备上直接跑识别模型，没有云端往返，延迟低且断网可用。

**2. Tauri v2 的轻量外壳。** 用 Rust 做后端、系统 WebView 做界面，安装包比 Electron 方案小一个量级，这对一个常驻工具很重要。

**3. 可扩展。** 支持自定义模型与热词，专有名词、人名、内部代号可以提前喂进去，识别率立刻不一样。

**4. 无障碍导向。** 面向听写、字幕、无障碍输入设计，落地场景天然是"替代键盘输入"而不是"做会议纪要 SaaS"。

## 安装与上手

从 Releases 下载对应平台安装包最省事；也可以自行构建：

```bash
git clone https://github.com/cjpais/Handy.git
cd Handy
cargo tauri build
```

第一次启动会下载识别模型，之后的转写不再需要网络。

## 点评

**亮点**是把隐私做成默认值而不是付费选项。在"什么都要上云"的语音赛道里，一个不联网、能换模型、还长得像正常桌面应用的方案，本身就稀缺。

**局限**：本地模型的准确率仍不如顶级云端模型，口音重、环境嘈杂时差距明显；首次使用要下模型，占空间也考验耐心；长音频的转写速度取决于本机算力，老机器会明显吃力；功能聚焦在听写，没有说话人分离、时间轴对齐这类会议场景能力。

**适合人群**：对音频合规敏感的专业人士（医疗、法律、咨询）；常写长文、想用口述提效的作者；以及不愿把语音交给云端的隐私敏感用户。
