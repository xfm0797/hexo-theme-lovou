## 它想解决什么问题

"个人 AI 助手"的概念讲了很多年，落地时常卡在两处：一是重，装一堆服务才能跑；二是忘，每次对话都从零开始。

nanobot 的取舍是**极简**：一个 Python 包就能起，把工具调用、长期记忆、多渠道接入做进去，不追求企业级编排。

## 核心机制拆解

**1. 依赖克制。** 启动快、部署简单，一台小机器甚至树莓派就能常驻，不需要一整套编排框架。

**2. 工具 + 记忆。** 内置工具调用与持久记忆，聊天之外能查、能记，跨会话不丢上下文。

**3. 多渠道。** 可接入多种消息通道，把助手挂在你日常用的聊天软件里，而不是再开一个网页。

**4. 多模型。** 便于切换或组合不同模型，简单任务用小模型、复杂任务换大的。

## 安装与上手

```bash
pip install nanobot
# 或使用官方 Docker 镜像自托管
nanobot --help
```

先配好模型 Key 与一个渠道，再让它记一条信息、隔天问回来——记忆链路通了才值得继续加功能。

## 点评

**亮点**是分寸感：它没有试图做"Agent 操作系统"，而是把"能记住我、能在我常用的聊天窗口里出现"这两件事做到够用。轻量带来的好处是随处可部署，长期挂着也不心疼资源。

**局限**：轻量的另一面是能力边界——复杂多步任务容易断，工具生态比不上成熟框架；记忆的检索与遗忘策略相对朴素，信息多了会互相干扰；多渠道接入的稳定性取决于各平台接口，容易受上游变动影响；文档偏简，很多行为要读代码确认。

**适合人群**：想在自己的服务器上养一个长期助手的技术用户；需要把 AI 接进日常聊天工具的人；以及研究轻量 Agent 记忆机制的开发者。
