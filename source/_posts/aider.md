# Aider

## 它想解决什么问题

大多数 AI 编程工具的第一步是"你把代码贴给它"。一旦项目超过几百行，这个前提就崩了：贴不全、贴错版本、贴完还得手工把改动搬回文件。

Aider 的做法是把边界前移：**它直接在你的仓库里工作**。读取相关文件、生成 diff、落到磁盘，改完自动 commit。你需要的不是复制粘贴，而是一句"把这个模块的错误处理补上"。

## 核心机制拆解

**1. 仓库级上下文。** 通过仓库映射（repo map）理解文件与符号之间的关系，按需把相关片段喂给模型，而不是无脑全量塞进去。这是它在大型项目上仍能保持准度的关键。

**2. 编辑即 diff。** 模型输出的是针对性修改，Aider 负责应用并校验；失败会回退重试，避免把文件改坏。**3. Git 原生。** 每次改动自动生成清晰的 commit，AI 与人的贡献在历史里可分辨，想撤销就是一次 revert。**4. 模型无关。** 支持主流云端模型与本地模型，成本与隐私自己权衡。

## 安装与上手

```bash
python -m pip install aider-install
aider-install
export ANTHROPIC_API_KEY=...   # 或 OPENAI_API_KEY
cd your-repo && aider
```

进去之后直接说需求，`/add` 指定文件、`/run` 跑测试、`/undo` 回滚，用的就是它内置的斜杠命令。

## 点评

**亮点**是把"AI 改代码"这件事做成了可审计的工作流：diff、commit、回滚，三个动作齐全，团队里其他人 review 起来和看人类提交没区别。这是它比聊天式工具更适合真实仓库的根本原因。

**局限**：上下文选择靠启发式，超大 monorepo 仍会出现"改错文件"；纯终端对习惯 IDE 的人有门槛；效果高度依赖模型质量与 prompt 习惯，换个弱模型体验断崖；自动 commit 在团队协作中需要配合分支策略，否则历史会很吵。

**适合人群**：长期在终端里工作的后端/系统开发者；希望 AI 改动可 review、可回滚的团队；以及想完全掌控上下文与模型选择、不愿被 IDE 插件绑定的工程师。
