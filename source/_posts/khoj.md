# khoj

> 把笔记、文档、邮件、代码都变成可对话的知识库，还能自己上网查资料、做深度研究

## 它想解决什么问题

你的知识散在 Obsidian、Notion、PDF、邮件和聊天记录里。搜索靠关键词，找得到原文却找不出结论；想问"我之前总结过的那套方案到底是哪几条"，只能靠记忆翻。

khoj 的定位是**面向个人知识库的 RAG 助手**：把这些来源索引起来，支持自然语言提问、增量更新，还能基于你的资料做多步研究并输出报告。

## 核心机制拆解

**1. 多源索引。** 笔记、Markdown、PDF、Word、图片（OCR）、邮件都能进索引；本地目录与在线服务均可，索引可定时增量更新。

**2. 语义检索 + 引用。** 回答带来源片段，能点回去核对，不是凭印象发挥。

**3. 自动化研究。** 给定问题，它会拆解成子问题、检索资料、汇总成带引用的文档——这类"研究型 Agent"能力是它区别于普通聊天入口的地方。

**4. 客户端齐全。** Obsidian、Emacs、桌面与 Web 都能用，聊天渠道还可接 WhatsApp 等，随手就能问。

## 安装与上手

```bash
docker run -d --name khoj -p 42110:42110   -v khoj_config:/root/.khoj   ghcr.io/khoj-ai/khoj:latest
```

打开 `http://localhost:42110`，接一个模型（本地或云端），再把笔记目录挂进去开始索引。

## 点评

**亮点**是"个人知识"这个切入点选得准：不是企业知识库那套重架构，而是围绕一个人已有的文件做检索与推理。AGPL + 自托管，意味着数据不出你的机器，这对笔记类产品几乎是硬要求。

**局限**：AGPL 对商业二次分发限制较强，公司内部用没问题，做成产品要慎；索引质量取决于资料组织程度，命名混乱的目录检索效果会打折；研究型任务耗时长、token 消耗不小；部署涉及向量库与模型服务，非技术用户上手偏难。

**适合人群**：笔记量大的研究者与写作者；想把自己的资料变成可问答知识库的工程师；以及对数据落地方案敏感的自托管玩家。
