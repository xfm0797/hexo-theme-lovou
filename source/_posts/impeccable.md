## 它想解决什么问题

AI 代理生成界面的质量评估现在靠"人眼把关"：截图、吐槽、打回重做——不可扩展。Impeccable 的定位一句话：**把设计质量从主观判断变成可执行的确定性检测**。它由三部分组成：一套成文的设计语言（间距、层级、对齐、动效的判断标准）、24 条可在会话中直接调用的设计命令、以及 59 条**确定性检测规则**——机器可判定"这个间距违反了规范"、"这处对比度不达标"，不靠模型自由发挥。

## 核心机制拆解

**1. 确定性检测是最大差异点。** 同类"AI 审美"项目大多靠规则文本影响模型输出，Impeccable 则内置 59 条可程序化执行的检测器：结果要么过要么不过，可挂进 CI、可循环修复。AI 改完 → 检测 → 不过 → 再改，形成自动收敛的质量闭环。

**2. 实时浏览器迭代。** 内置 live browser iteration 工作流：命令驱动代理在真实浏览器里改样式、截图对比、即时修正——不是"盲改代码再祈祷"。

**3. 24 条设计命令。** 从"审计这个页面的视觉层级"到"按规范重做这套配色"，命令把高频设计动作标准化，团队可以像用 lint 一样用设计规范。

**4. 与 Taste Skill 的分工。** taste 管先天的审美取向（生成时影响），impeccable 管事后的质量把关（检测时兜底）——很多团队两个一起装，一个当设计总监，一个当 QA。

## 安装与上手

按所用 AI 代理（Claude Code / Codex / Cursor 等）的技能规范安装后即可使用全部命令；检测规则可独立运行，适合接入现有的前端质量门禁。

## 点评

**亮点**是思路上的升级：把"AI 设计不好看"这个玄学问题，拆成了 59 条可机判的确定性问题——这是工程化思维对审美话语权的收编；作者 Chrome DevTools 出身，对"在浏览器里迭代"的理解是实打实的；8 万+ 星的单日增速证明这个方向正当红。

**局限**：确定性规则只能覆盖可量化的设计维度（间距、对比度、对齐），构图、创意、品牌感仍然管不到；规则集更新依赖作者节奏；对非 Tailwind/常规 CSS 体系的项目，部分检测器需要适配。

适合人群：用 AI 代理批量生成界面的团队，尤其是想给"AI 产出的前端"建质量门禁的工程组织——把它当 AI 时代的 ESLint 来理解就对了。
