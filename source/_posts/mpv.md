# mpv

> 脱胎于 MPlayer 的命令行播放器：界面克制到近乎不存在，渲染质量与可脚本化做到极致

---

> **项目速览**
>
> | 项目 | 内容 |
> | --- | --- |
> | 仓库 | [mpv-player/mpv](https://github.com/mpv-player/mpv) |
> | 语言 | C（解码依赖 FFmpeg） |
> | 协议 | GPL-2.0+ / LGPL-2.1+（按构建选项而定） |
> | 平台 | Linux / macOS / Windows 等 |
> | 扩展 | Lua 脚本体系 |
> | 渲染 | GPU 视频输出：Vulkan / OpenGL / Direct3D / Metal |

## 它想解决什么问题

大多数播放器在"功能"上做加法：皮肤、推荐、弹幕、片库管理、在线内容聚合。mpv 走的是反方向——**默认没有边框、没有菜单、没有推荐，只有画面**。所有能力都藏在命令行参数与配置文件里。

这个选择把它推向了另一类用户：技术玩家、需要在脚本里控制播放的工程师、把它当播放后端的上层工具（下载器、前端、信息屏、展厅系统）。对这些场景，"界面"本身就是噪音。

## 核心机制拆解

**1. 极简体验。** 双击即播，同时提供按需启用的 OSC 控制条。默认干净到你会怀疑是不是少了什么——这是设计意图，不是缺失。

**2. GPU 视频输出。** 基于 GPU 的渲染后端覆盖 Vulkan / OpenGL / Direct3D / Metal，支持色彩管理、HDR、插值等高级特性。画质这件事上它一贯比商业播放器更"较真"：缩放算法、色域映射、去色带都能手动指定。

**3. Lua 脚本扩展。** 通过 Lua 几乎可以定制一切行为，社区有丰富的脚本生态（字幕增强、播放列表、界面替换等）。轻量脚本语言挂在一个 C 内核上，扩展性与稳定性兼得。

**4. 命令行优先。** CLI 参数完整且一致，便于脚本化与管道集成；也正因如此，常被其他前端与 `yt-dlp` 之类工具当作播放后端调用。

**5. 格式支持靠 FFmpeg。** 几乎任何主流音视频与字幕格式都能播——因为它把解码这层直接交给了 FFmpeg，等于借了整个生态的力。

## 安装与上手

```bash
# macOS
brew install mpv

# Debian/Ubuntu
sudo apt install mpv
```

几条高频用法，能立刻感受到它的取向：

```bash
mpv video.mkv                        # 直接播放
mpv --no-audio video.mkv             # 仅视频
mpv --speed=1.5 video.mkv            # 倍速
mpv --ytdl "https://youtu.be/xxxx"   # 配合 yt-dlp 播在线视频
```

真正上手之后，你会开始写 `mpv.conf` 与 `input.conf`——那才是它的"设置界面"。

## 点评

**亮点**是"克制"这件事被执行得彻底：不堆功能，而是把渲染质量与可扩展性推到极致。对一个已有二十多年谱系（MPlayer → mplayer2 → mpv）的项目来说，能守住这个取向而不被功能诉求带偏，本身就是工程文化。

**局限**也很直接：**它对普通用户不友好**——没有片库、没有图形化设置、拖进度条这种"基本操作"都要靠 OSC 或快捷键；出问题时输出的是命令行日志，而不是"请检查网络"这样的提示；Windows 上的安装与关联格式需要手动折腾；Lua 脚本生态虽然丰富，但质量参差且多数无人维护，装多了互相打架；HDR 与色彩管理要正确工作，对显卡驱动与配置有要求。

**适合人群**：追求干净观影体验、不想要花哨 UI 的用户；需要在脚本或自动化里控制播放的场景（展厅、信息屏、监控回放）；以及把播放能力嵌进自己工具链的开发者。

对开发者与极简主义者来说，它几乎是命令行播放器的终点——前提是你能接受"配置即界面"。
