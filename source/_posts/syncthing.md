# Syncthing

> 开源 P2P 同步：设备之间直连传输、全程加密，没有中心服务器，也没有容量上限

## 它想解决什么问题

网盘的核心矛盾是"便利"与"控制权"的交换：文件存在别人机房、容量要付费、同步策略由平台决定，服务关停你还得搬家。

Syncthing 走的是相反方向：**设备之间直接同步**，没有中心存储，传输全程加密（TLS + 设备证书），容量只取决于你自己的硬盘。

## 核心机制拆解

**1. P2P 直连。** 设备通过发现服务找到彼此，优先局域网直连，跨网时用中继兜底，数据不落在第三方磁盘上。

**2. 设备身份即证书。** 每台设备一对密钥，首次配对需交换设备 ID，未经确认的设备无法加入——这层比账号密码更硬。

**3. 版本与冲突处理。** 支持文件版本保留与冲突副本策略，多端同时改不会静默覆盖。

**4. 选择性同步。** 大目录可按需同步子集，NAS 上尤其有用。

## 安装与上手

```bash
docker run -d --name syncthing -p 8384:8384 -p 22000:22000/tcp -p 22000:22000/udp   -v /path/to/config:/var/syncthing/config   -v /path/to/data:/var/syncthing/data syncthing/syncthing
```

打开 `http://localhost:8384`，添加远程设备并互相确认 ID，再共享文件夹。

## 点评

**亮点**是架构上的彻底：没有中心就没有容量费、没有服务关停风险、没有"我们的隐私政策更新了"。设备证书机制让安全模型简单而可靠，适合长期运行。

**局限**：移动端的后台同步受系统限制，常需前台保持；跨网中继速度取决于中继节点，大文件传输不如商业网盘稳；没有内建的分享链接能力（给别人临时下载要另外搭）；冲突处理是"保留两份"而不是合并，需要人工介入；设备多了管理成本上升。

**适合人群**：多设备同步笔记与照片的个人用户；有 NAS、希望数据自持的家庭与小团队；以及开源项目的多节点文件分发。
