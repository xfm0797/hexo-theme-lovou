## 它想解决什么问题

过去两年，提升 Agent 表现的主流路径是换模型：更强的基座、更长的上下文、更多的 RL。Harness² 把赌注押在相反方向——**模型权重固定不变，只优化模型外面那一圈**。

先对齐术语：Harness（马具）指让模型能作为 Agent 行动的整套系统——提示词、工具、记忆、技能、编排逻辑；Harnessing 就是优化这套系统。社区已有一堆手工调优项目，但问题是：开放世界里 Agent 遇到的任务在设计 harness 时根本没见过，手工调优永远追着任务跑。

Harness² 的答案是**递归**：让 Agent 在自己的执行证据基础上自动改写自己的 harness，分两个层次——

## 核心机制拆解

**1. 任务级递归：Propose–Probe–Compose。** 针对当前任务，通过"提议—试探—组合"三步细化执行 harness：先提出修改，在同一任务上试探效果，再从多次执行的行为对比中组合出更优版本。关键在于：**整个过程不需要标准答案反馈**——只靠 Agent 自身行为的对比证据。

**2. 马具级递归：经验沉淀。** 把每个任务采纳的 harness 和"有证据支持的经验教训"沉淀进持久化的 improvement harness，指导下一次任务的精修——Agent 越用越强的机制由此成立。

**3. 研究配套完整。** 论文（arXiv:2610.14224）、官网、基准测试一应俱全，属于可复现的研究工程而非纯 demo。

## 安装与上手

Python 3.12 + uv 环境，按仓库 README 安装运行；建议配合论文阅读理解递归机制的设计动机。

## 点评

**亮点**：方向判断有洞察力——模型能力进入平台期后，harness 层的自动优化就是最大的增量来源；"无需标准答案的行为对比"绕开了强化学习对奖励信号的依赖，这对开放域任务尤其重要；Google Research 背书 + 论文配套，严谨度高。

**局限**：两周破万星的热度中研究属性大于生产属性，直接用于业务需自己评估；递归自改写带来的行为不可预测性需要护栏；README 自述"非 Google 官方支持产品"。

适合人群：Agent 方向的研究者与工程师、做 Agent 平台需要持续调优 harness 的团队、以及所有关注"模型之外还有什么可优化"的人。
